Blockchain: Peer-to-Peer Cryptocurrency System

I developed a functional cryptocurrency system built on blockchain technology. The system includes a distributed network of nodes that can mine blocks, process transactions, and maintain a synchronized blockchain across the network.

System Architecture

1. Blockchain Implementation

The core of the system is a blockchain implementation featuring:

  • Proof-of-work consensus mechanism with adjustable difficulty
  • Transaction validation and processing
  • Automatic mining rewards (10% transaction fee)
  • Chain synchronization across nodes

2. Node Network

Each node in the network can:

  • Broadcast transactions to all active nodes
  • Mine new blocks with valid transactions
  • Receive and process blockchain updates from peers
  • Maintain a local copy of the blockchain
  • Track account balances based on transaction history

3. User Interface

The system includes a console-based wallet interface that allows users to:

  • Send ChimChimCoins to other users in the network
  • View current account balance
  • View active nodes in the network
  • Examine the blockchain's transaction history

Technical Implementation

The project is implemented in Python and takes advantage of:

  • Socket programming for network communication
  • Multithreading for concurrent processing (mining, network listening, etc.)
  • JSON for data serialization and blockchain storage
  • Cryptographic hashing for block validation
  • Queue management for transaction processing

Challenges & Solutions

  • Blockchain Synchronization: Implemented a mechanism to compare chain lengths and resolve conflicts by selecting the longest valid chain
  • Concurrent Transaction Processing: Used thread-safe queues to manage incoming transactions while mining
  • Network Resilience: Implemented error handling and peer management to handle node connections and disconnections

Key Features

  • Decentralized architecture with no central authority
  • Transparent transaction ledger accessible to all network participants
  • Secure cryptographic validation of transactions
  • Economic incentives for miners through transaction fees

Literary Text Embedding Analysis for Emotional Clustering

At Columbia's CRIS Lab (Computational Research on Interpretations and Semantics), I developed a computational pipeline to investigate whether language model embedding spaces naturally cluster by emotional content. This project involves processing over 40 literary texts spanning horror, fantasy, mystery, romance, and other genres from the Gutenberg library, transforming them into vector representations, and analyzing the resulting embedding space.

Project Pipeline

1. Text Preprocessing & Chapterization

My pipeline begins by organizing literary texts from the Gutenberg corpus by genre. The process includes:

  • Automated chapter detection using both standard and custom chapterization algorithms
  • Cleaning texts to remove metadata, headers, and other non-narrative content using the Gutenberg Cleaner library
  • Handling edge cases where standard chapterization fails with a fallback custom solution
  • Preserving genre information throughout the processing pipeline

The code systematically processes each book within its genre directory, creating a well-structured dataset of chapters ready for vectorization.

2. Text Vectorization & Embedding Generation

The second phase transforms the cleaned, chapterized text into high-dimensional vectors:

  • Using transformer-based models to generate contextual embeddings
  • Extracting [CLS] token representations as chapter-level embeddings
  • Maintaining the association between embeddings and their source genres
  • Handling long texts through appropriate truncation and padding strategies

Each chapter is independently vectorized, creating a rich dataset of embeddings that capture the semantic and potentially emotional characteristics of the text.

3. Embedding Space Analysis

We are currently working on this phase of the project. This final stage involves analyzing the embedding space to determine if emotional content naturally clusters based on the vector representations generated in the previous step.

Technical Challenges

  • Processing a diverse corpus with inconsistent formatting
  • Handling long literary texts within the context window constraints of transformer models
  • Developing fallback mechanisms for texts that resist standard chapterization
  • Managing memory constraints when generating embeddings for large datasets

Impact

This research contributes to our understanding of how language models encode and process emotions in text. The findings may inform future model design and provide insights into how artificial neural networks represent complex human emotional concepts.

Technologies

Python, PyTorch, Hugging Face Transformers, BERT, AutoTokenizer, scikit-learn for visualization and clustering
